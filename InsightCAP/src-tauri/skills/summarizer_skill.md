# Summarizer Skill — 對話總結規範

## 用途

本規範定義 InsightCAP 在用戶離開對話或手動觸發時，產生對話總結（Summary）的 Prompt 格式與輸出期望。
遵循 ADR-017「離開即儲存」觸發邏輯。

## Prompt 格式

```
你是筆記整理助手。請用繁體中文整理以下對話。

規則：
1. 只寫繁體中文，不要用簡體字
2. 直接輸出內容，不要任何標題或標籤
3. 分三段落輸出，段落之間空一行
4. 每段至少 3-4 句完整的句子，確保涵蓋對話從頭到尾的所有重要資訊

第一段：這次對話的核心主題，以及後續延伸討論了哪些具體子話題。
第二段：對話中提到的重要細節，包括具體的清單、數據、餐單建議、或是特定事物的分析。
第三段：最終結論、產出的解決方案或對話的最終共識。

對話記錄：
{conversation_text}

請開始整理：
```

## 觸發邏輯 (ADR-017)

系統在以下時機嘗試進入隊列（`conversation_summary_queue`）：
- **過濾機制**：
  - 消息數 >= 5（避免無意義的總結）。
  - 對話冷卻期 > 10 分鐘（避免頻繁更新）。
  - 當前是否有待處理任務。
  - 上次總結後是否有新消息增加。
- **儲存位置**：
  - 生成的總結存入 `chunks` 表。
  - `type` 設為 `conversation`。
  - `space_id` 設為原始對話所屬空間或 `inbox-space-id`。

## 模型選擇建議

建議優先選擇具備良好長文本理解與繁體中文能力的模型：
- **Qwen2.5 7B/14B**（推薦：中文處理最優）。
- **Llama 3.1 8B**（邏輯稍強，但簡繁體處理需注意）。

## 失敗處理與重試

- **備份機制**：生成失敗時，寫入「對話包含 X 條消息，總結生成失敗」佔位字。
- **標記**：設置 `tags` 為 `["summary-error"]`。
- **異步性**：此工作由 `Background Capture Processor` 在後台閒置時執行。
