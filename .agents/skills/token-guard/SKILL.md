在每次對話開始或任務執行前，評估 token 消耗風險，防止大量浪費。

## 觸發時機
- 任務涉及讀取大量檔案（超過 5 個）
- 任務描述模糊、範圍不明確
- 使用者要求掃描整個資料夾或 codebase
- 對話 context 使用量超過 50%

## 執行步驟

**1. 任務風險評估**
在執行任何大範圍操作前，先回答：
- 需要讀幾個檔案？預估每個多少行？
- 是否可以用 Grep / Glob 取代全文讀取？
- 任務是否可以拆成更小的子任務？

**2. 高風險操作攔截**
以下操作必須先詢問使用者確認才能執行：
- 讀取超過 5 個檔案
- 讀取單一檔案超過 300 行（需指定 offset + limit）
- 執行會產生大量輸出的指令（cargo build、npm run build）
- 對整個目錄做 grep 且無 --include 過濾

**3. 節省策略（優先順序）**
1. Grep 搜尋關鍵字 → 只讀命中的檔案
2. Glob 找到目標檔案 → 只讀必要段落（offset + limit）
3. git diff 取得變更 → 只處理有變更的檔案
4. 禁止使用 @codebase 或讀取整個資料夾

**4. Context 使用量警示**
每完成一個子任務後，提醒：
- 若 context 已超過 50%：「建議執行 /compact 後繼續」
- 若 context 已超過 75%：「強烈建議立即 /compact，否則後續回應品質會下降」

**5. 輸出報告格式**
```
【Token 使用評估】
預計讀取檔案：N 個
預計消耗 token：約 N k
風險等級：低 / 中 / 高
建議：[具體節省方案]
```
高風險時暫停執行，等使用者確認後才繼續。
